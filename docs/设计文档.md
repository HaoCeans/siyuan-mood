# 心情管理插件（siyuan-mood）设计文档

> 状态：设计稿 v1 · 2026-09-25
> 目标读者：本插件的实现者（我自己）

---

## 0. 定位与边界

一句话：**用随机心情问答记录此刻状态，借思源自带的 AI 解读，把「建议」落到「实际做了什么、之后感觉如何」，并用曲线和提醒把这个循环持续下去。**

四条功能主线与设计边界：

| 功能 | 说明 | 边界 |
|---|---|---|
| 心情问答 | 默认从题库随机抽 10 题，单选/多选，每次问答存成一张卡片 | 只问「此刻」，不问「你平时怎样」 |
| AI 解读 | 走思源内核 AI 通道，输出心情状态 + 关键词 + 建议 + 填空位 | 不做医学诊断，不贴人格标签 |
| 统计 | 心情曲线、维度雷达、日历热力、关键词频次、记录表格、AI 周报 | 图表全部手写 SVG，不引入第三方图表库 |
| 提醒 | 依据曲线算出下次该测的间隔，到期提醒 | 静默时段不打扰，一天最多提醒一次 |

数据全部保存在思源工作空间内（`data/storage/petal/siyuan-mood/`），随思源同步走，插件本身不联网、不落任何 key。

## 3. 数据模型

`src/types/mood.ts`：

```ts
// ---------- 题库 ----------
export type Dimension = "body" | "recognition" | "energy" | "avoidance" | "need";

export interface DimensionMeta {
  key: Dimension;
  name: string;         // 身体觉察 / 情绪识别 / 能量状态 / 情绪回避 / 当下需求
  scored: boolean;      // 是否计入心情分（need 不计分，只用于建议与关键词）
  weight: number;       // 计入心情分时的权重
}

export interface QuizOption {
  id: string;
  label: string;        // 选项文本
  score?: number;       // 0-3，越大越「此刻平稳 / 觉察在线」；不计分维度可省略
  tags?: string[];      // 关键词候选，如 ["紧绷", "焦虑"]
}

export interface QuizQuestion {
  id: string;
  dimension: Dimension;
  type: "single" | "multiple";
  text: string;
  options: QuizOption[];
  source: "builtin" | "imported";
  enabled: boolean;
  weight?: number;      // 默认 1
}

export interface QuestionBankFile {   // 导入文件格式
  schema: "siyuan-mood-bank";
  version: 1;
  name?: string;
  questions: QuizQuestion[];
}

// ---------- 记录 ----------
export interface QuizAnswer {
  questionId: string;
  questionText: string;              // 快照：题库被导入覆盖后，历史记录仍可回看
  dimension: Dimension;
  optionIds: string[];
  optionLabels: string[];            // 快照
  score: number;                     // 该题得分 0-3
  tags: string[];                    // 该题带来的关键词候选
}

export interface AiAdvice { id: string; text: string; }

export interface AiAnalysis {
  status: "idle" | "running" | "done" | "failed";
  mood?: string;                     // 「低能量 + 情绪模糊 + 轻度回避」
  keywords?: string[];               // 3-5 个
  analysis?: string;                 // 一段话（Markdown）
  advice?: AiAdvice[];                // 2-3 条，可执行的小动作
  practice?: string;                 // 本周练习
  changes?: string;                  // 与上次相比的变化（第二次起才有）
  raw?: string;                      // 原始返回，JSON 解析失败时兜底渲染
  error?: string;
  at?: number;
}

export interface FollowUp {
  adviceId: string;
  adviceText: string;                // 快照
  done: "unset" | "yes" | "partial" | "no";
  blocker?: "forgot" | "hard" | "unwilling" | "no-time" | "other";
  feeling?: number;                  // 1-5：照做之后的心情
  note?: string;                     // 填空：真正实施之后的感受
  at?: number;
}

export interface QuizRecord {
  id: string;                        // 20260925-2130-ab12
  startedAt: number;
  finishedAt: number;
  questionIds: string[];
  answers: QuizAnswer[];
  dimensionScores: Partial<Record<Dimension, number>>;  // 0-100
  moodScore: number;                 // 0-100，越高越平稳
  keywordLocal: string[];            // 本地提取，AI 未跑或失败时也能显示
  ai: AiAnalysis;
  followUps: FollowUp[];
  dueAt?: number;                    // 本次算出的下次建议时间
  note?: string;
}

// ---------- 设置 ----------
export interface MoodSettings {
  questionsPerQuiz: number;          // 默认 10
  repeatTolerance: number;           // 与上次题目重复率上限，默认 0.5
  bank: { useBuiltin: boolean; importedEnabled: boolean };
  reminder: {
    enabled: boolean;
    baseDays: number;                // 默认 7
    minDays: number;                 // 默认 1
    maxDays: number;                 // 默认 30
    quietFrom: string;               // "22:00"
    quietTo: string;                 // "08:00"
    lastPromptAt?: number;
  };
  ai: {
    enabled: boolean;
    autoRun: boolean;                // 提交后自动解读
    maxContextRecords: number;       // 提示词里带几次历史，默认 3
    promptExtra?: string;            // 用户追加的提示词
  };
}
```

### 存储布局

用插件自带的 `this.loadData(name)` / `this.saveData(name, data)`（落在 `data/storage/petal/siyuan-mood/<name>.json`，随思源同步）：

| 文件 | 内容 | 频率 |
|---|---|---|
| `settings` | `MoodSettings` | 改设置时 |
| `bank` | 导入的题库 | 导入/删除时 |
| `index` | 轻索引：`{id, finishedAt, moodScore, keywords, followUps 完成情况}` | 每次记录后 |
| `rec-YYYY-MM` | 该月记录明细数组 | 每次记录后只写当月文件 |

分月切片的原因：记录会长期增长，单文件每次全量重写会越来越慢；索引文件小，列表与统计先用索引渲染，点开某条卡片时才按 `finishedAt` 去对应月份文件取明细。P0 阶段可以先用单文件 `records`，存储层统一封装，后续替换不影响 UI（接口 `listIndex()` / `getRecord(id)` / `putRecord(r)` / `removeRecord(id)` / `exportAll()` / `importAll()`）。

## 4. 题库与抽题

### 内置题库（`src/quiz/bank.ts`）

24 题起步，5 个维度，单选题为主，附 4 道多选题。选项自带 `score` 与 `tags`，例如：

```ts
{ id: "body-1", dimension: "body", type: "single", source: "builtin", enabled: true,
  text: "现在，你身体哪个部位的感觉最明显？",
  options: [
    { id: "A", label: "能清楚说出一个部位（比如肩膀发紧、胃部发空）", score: 3, tags: ["身体信号清晰"] },
    { id: "B", label: "大概有感觉，但说不清具体在哪", score: 2, tags: ["身体信号模糊"] },
    { id: "C", label: "没什么特别的感觉", score: 1, tags: ["身体钝感"] },
    { id: "D", label: "身体很沉、很累或很紧，但不太想去感受它", score: 0, tags: ["身体过载"] },
  ] },
```

各维度题量：身体觉察 4、情绪识别 4、能量状态 4、情绪回避 4（反向计分：越回避越低分）、当下需求 4 单题 + 4 道多选题（信号清单 / 应对方式 / 困扰类型 / 需要的帮助）。

多选题示例（关键词产量最高）：

```
此刻你身上出现了哪些信号？（可多选）
A 肩膀或脖子紧  B 胸口闷或空  C 胃部不适  D 下巴咬紧  E 手心出汗  F 什么都没感觉到
```

### 抽题策略（`src/quiz/picker.ts`）

1. 分层抽样：4 个计分维度各抽 2 题，`need` 维度抽 2 题（其中至少 1 道多选），合计 10 题。
2. 打乱顺序，但保证同一维度的题不相邻。
3. 重复控制：与上一条记录比对，若重复率 > `repeatTolerance`（默认 0.5）则重抽，最多 5 次，超限就接受。
4. 题量不足时（导入题库太小）：按实际可用题量降级，并在 UI 上提示「题库不足，本次 6 题」。

### 导入格式

设置面板「导入题库」接受 JSON 文件（`<input type="file">`）或粘贴文本，校验规则：`schema === "siyuan-mood-bank"`、每题 `id/dimension/text/options` 齐备、`dimension` 在允许集合内、`type` 为 `single|multiple`、单选选项数 ≥ 2。校验失败给出逐条错误行号，不写库。导入的题与内置题并存，`bank.useBuiltin` 可整体关掉内置题。

## 5. 计分与关键词

`src/quiz/score.ts`：

- **单题得分**：单选取所选选项 `score`；多选取所选选项 `score` 的平均值；未设 `score` 的题（`need` 维度）不计分。
- **维度分**：`dimensionScore = Σ(score × weight) / (3 × Σ(weight)) × 100`，四舍五入到整数。
- **心情分**：仅计 `scored` 维度，`moodScore = Σ(dimScore × dimWeight) / Σ(dimWeight)`，默认权重 身体 0.2 / 识别 0.25 / 能量 0.25 / 回避 0.3…… **注意**：权重是产品参数，第一版先取等权（各 0.25）跑一两周再调，避免用拍脑袋的权重当结论。
- **等级文案**（只描述此刻，不描述人）：80+ 平稳在线 / 60-79 大体平稳有起伏 / 40-59 有波动，值得停一停 / 20-39 偏低，先照顾身体 / 0-19 很低，先安抚，必要时找信任的人聊聊。
- **本地关键词**：把所选选项的 `tags` 按出现次数排序取前 5，存入 `keywordLocal`。它的作用是不依赖 AI 也能显示关键词——AI 失败时卡片不至于空着。

**措辞规范（写进提示词也写进 UI 文案）**：不说「你有焦虑倾向」「你属于回避型」，只说「此刻的状态偏……」「这个模式看起来是……」。目的是不制造焦虑。

## 6. AI 解读

### 调用方式（复用已验证的内核通道）

`src/utils/siyuanAi.ts` 直接采用另一插件已跑通的方案，要点全部保留：

- 走 `fetchSyncPost("/api/ai/chatGPT", { msg })`，模型/厂商/Key 全由思源「设置 → AI」决定，插件不留 key。
- **每次请求前先发一次 `{ msg: "Clear context" }`**：内核的会话上下文 `cachedContextMsg` 是进程级全局变量，不清就会串入上一次请求（甚至思源自带功能、其他插件）的历史。
- **失败判定看 `data` 不看 `code`**：未配置 AI 时返回 `code: 0` 且 `data: ""`，必须按空字符串判失败。
- 请求期间内核会插入 `#progress` 全屏进度条，用 `MutationObserver` 清掉，并在 `onunload` 统一 `disconnect`。
- Markdown 渲染用全局 `Lute`：`Lute.New().Md2HTML(md)`；拿不到时降级为 `\n` → `<br>`。
- **加一个串行队列**（单飞 Promise 链）：本插件有「提交后解读」和「生成周报」两个入口，并发调用会互相冲掉内核上下文。
- 被调用方返回统一结构 `{ ok, markdown, reason?: "empty" | "failed" }`，任何异常都不向主流程抛。

想要打字机效果时可换 `/api/ai/editor/chat`（SSE，事件 `start` / `reasoning` / `content` / `truncated` / `done`），但它是编辑器专用、需要预置 action，第一版不用；把它作为后续增强项，同样封在 `siyuanAi.ts` 内。

### 提示词（`src/ai/prompts.ts`）

`/api/ai/chatGPT` 没有 system role，全部写进 `msg`，并要求**只输出 JSON**：

```
你是一位温和、不评判的情绪觉察教练。下面是用户刚刚完成的一次自评。
请只输出一个 JSON 对象，不要输出解释性文字，不要使用代码块围栏。

<本次作答>
心情分：34
维度得分（0-100）：身体觉察 48 / 情绪识别 31 / 能量状态 25 / 情绪回避 60
问答明细：
- [身体觉察] 现在，你身体哪个部位的感觉最明显？ → 没什么特别的感觉
- [能量状态] 此刻你的能量水平： → 有点累，想躺着
- [情绪回避] 此刻你有没有正在躲开的东西？ → 有，正在用刷手机等方式躲开
</本次作答>

<输出要求>
1. 描述此刻状态，不做医学诊断，不使用"你有…症""你是…型人格"这类标签。
2. advice 给 2-3 条，必须是能在 10 分钟内做完的具体小动作，不写"要放松""多运动"。
3. keywords 给 3-5 个，中文短语，来自上面的作答，不要生造。
4. 若用户状态很低（心情分 < 20），第一条 advice 以安抚身体为主，不布置任务。

<输出格式>
{
  "mood": "低能量 + 情绪模糊 + 轻度回避",
  "keywords": ["疲惫", "情绪模糊", "刷手机回避"],
  "analysis": "一段 2-3 句的描述……",
  "advice": [{ "text": "先做 3 次慢呼吸，然后去接一杯水" }, { "text": "把手机放到另一个房间 10 分钟" }],
  "practice": "今晚睡前写一句：今天身体最明显的感受是____"
}
</输出要求>
```

**第二次及以后**在 `<本次作答>` 之前插入 `<历史对比>`：上 1-3 次的日期、心情分、维度分、关键词，以及上次建议的执行情况（`done` / `feeling` / `note`），并要求额外输出 `changes` 字段（哪个维度动了、上次哪条建议有效、哪条卡住了、卡在哪）。这就是「AI 建议越来越贴合」的机制来源：**把「实际解决情况」喂回去**。

### 解析与容错（`src/ai/analyze.ts`）

1. 从返回文本中提取 JSON：先找 ```json 围栏，再退化为「第一个 `{` 到最后一个 `}`」的括号配对截取。
2. `JSON.parse` 成功 → 写入 `record.ai`（`status: "done"`），`advice` 逐条补 `id`，同步生成 `followUps`（`done: "unset"`）。
3. 解析失败 → `status: "failed"`，把原文存进 `raw`，详情页照常渲染 Markdown，并给一个「重新解读」按钮。
4. `reason === "empty"` → 提示「尚未在 设置 → AI 中配置模型」，附一句「配置好后回来点重新解读」，不弹错误框。
5. 记录里保存 `ai.at` 时间戳，便于区分「AI 解读于何时」。

## 7. 记录卡片与跟进闭环

**卡片**（Dock 列表项，一行信息密度优先）：

```
09-25 21:30   ● 34          [低能量] [情绪模糊] [刷手机回避]
低能量 + 情绪模糊 + 轻度回避     建议 3 条 · 已做 1 · 未完成 2    >
```

字段：日期、心情分（色点按等级上色）、3 个关键词 chip、AI 状态首行、跟进进度。`ai.status === "running"` 显示占位骨架，`failed` 显示「未解读 · 点击重试」。

**详情页**：完整作答明细（题干 + 所选选项）→ AI 解读（Markdown 渲染）→ 建议列表，每条建议下方一行跟进控件：

```
[做了] [部分做了] [没做]      照做之后心情：1 2 3 4 5
填空：真正实施之后我的感受是 ____________   [保存]
```

「没做」时展开「卡在哪」：忘了 / 太难 / 不想做 / 没时间 / 其他。**没做本身是数据**，用于下次 AI 调低建议难度，UI 文案不出现任何责备。

**闭环提醒**：给出建议 3 天后，若仍有 `done === "unset"` 的跟进项，提醒文案改成「上次的建议你试了吗？」[做了][没做][部分做]，点选后追问感受分与填空。这些数据在下一次 AI 解读时自动带上（§6 的历史对比）。

P3 可选：把某条记录以 Markdown 形式插入当前打开文档（`insertBlock`），方便在日记里留档。

## 8. 统计与图表

`src/stats/aggregate.ts` 负责算，`src/ui/charts/*.vue` 只负责画（纯 SVG，无第三方依赖，全部用 `--b3-theme-*` 变量配色，自动跟随主题与暗色模式）。

| 图表 | 内容 | 细节 |
|---|---|---|
| 心情曲线 | 时间 × 心情分折线 + 7 日移动平均虚线 | 点 hover 显示日期/分数/关键词；区间 7/30/90/全部 |
| 维度雷达 | 本次 vs 上次 vs 近 30 天均值 | 四轴（need 不计分不入图） |
| 日历热力 | 近 12 周，每格一天，颜色按心情分 | 无记录的格子留空，不当作 0 分 |
| 关键词频次 | 横条 top 10 | 只统计 AI 与本地关键词合并后的频次 |
| 记录表格 | 日期/心情分/各维度分/关键词/跟进完成率 | 支持导出 CSV |
| AI 心情卡片 | 把最近 N 条记录的摘要交给 AI，输出一段状态总结 + 3 个关键词 + 一句提示 | 手动触发，缓存到 `stats` 存储，卡片可追溯生成时间 |

统计视图放在 Dock 内的 Tab 切换（记录 / 统计 / 表格），避免再开窗口。

## 9. 提醒调度

`src/stats/reminder.ts`，**本地算法给基线，AI 只在允许区间内微调（可选）**：

```
interval = clamp(baseDays + adjust, minDays, maxDays)      // base 7, min 1, max 30
adjust = 0
  最近 3 次心情分斜率 < -1.5/次          → -3
  最近 5 次标准差 > 15                   → -2
  上次存在 done === "unset" 的跟进        → -1   （促进闭环）
  近 7 天均值 > 75 且标准差 < 8           → +3
  近 7 天已完成 ≥ 2 次                    → +2   （已足够密，别打扰）
dueAt = finishedAt + interval 天，且不早于「明天同一时间」
```

**检查时机**：`onload` 后 90 秒首次检查（避开思源启动期）；每 30 分钟 `setInterval`；每次问答完成、设置变更后立即重算。所有 timer 在 `onunload` 清理。

**触发表现**：顶栏图标加红点 + `fetchSyncPost("/api/notification/pushMsg", {msg, timeout})` 一条短提示；点图标进入对话框，提供 [现在开始] [今天稍后] [今天不再提醒]。静默时段（默认 22:00-08:00）只记红点、不弹提示；`lastPromptAt` 保证一天最多主动提醒一次。

## 12. 风险与对策

| 风险 | 对策 |
|---|---|
| `/api/ai/chatGPT` 是内核内部接口（apicontract），跨版本可能变 | 全部封装在 `utils/siyuanAi.ts`；返回 `{ok, reason}` 不抛异常；失败时降级为本地关键词 + 手动「重试」 |
| 内核 AI 上下文是进程级全局，会被别的调用串扰 | 每次请求前 `Clear context`；插件内加串行队列；多轮历史自己在提示词里拼 |
| 未配置 AI 时接口「成功但空」，容易误判为正常 | 一律按 `data` 是否为空判失败（§6） |
| 记录长期增长导致存储变慢 | 索引 + 按月分片；列表只读索引；导出/导入走 `storage.ts` 统一接口 |
| 移动端 Dock 不可用 | 入口退化为顶栏图标 + 命令；对话框 `92vw` |
| Vue 应用挂载/卸载泄漏（模板里的老毛病） | `main.ts` 统一 `mountVue/unmountVue`；顶栏、状态栏、快捷键、timer、MutationObserver 全在 `onunload` 清理 |
| 措辞造成焦虑 | 固定文案规范（只描述此刻状态）；提示词里显式禁止诊断与标签；低分离先安抚后行动 |
| 隐私 | 数据只存本地工作空间并随思源同步；只发往用户自己在思源里配置的模型；导出文件不含任何凭证 |
